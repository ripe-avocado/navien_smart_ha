# 나비엔 스마트 → Home Assistant

경동나비엔 **나비엔 스마트** 앱에 등록된 기기를 Home Assistant 에 붙입니다.
공식 API 가 아닙니다. 앱이 쓰는 서버를 그대로 사용합니다.

## 무엇이 되나

| 기기 | 지원 | 비고 |
| --- | --- | --- |
| 숙면매트 — 단계로 동작 | **됩니다** | 실기기(EME-500 싱글·더블)로 검증 |
| 숙면매트 — 온도로 동작 | 됩니다 (**미검증**) | 온도조절기가 생깁니다. 실기기 확인 전입니다 |
| 숙면매트 — 사계절 | **난방만** | 냉방 중에는 제어가 비활성됩니다. 아래 참고 |
| 환기청정 (에어원) | 됩니다 (**미검증**) | 신형만. `NRT-530S3`·`NRT-530Z3` 확인됨 |
| 보일러 | 안 됩니다 | **제보 받습니다** (시점은 약속 못 드립니다) |
| 월패드 · 로비폰 | 안 됩니다 | 범위가 아닙니다 |
| 상업용 SCADA | 안 됩니다 | 범위가 아닙니다 |

지원하지 않는 기기는 **건너뛰고 로그에 이유를 남깁니다.** 추측해서 제어하지 않습니다.

### 내 모델이 되나요?

**Wi-Fi 모델이면 됩니다. 블루투스 전용 모델은 안 됩니다.**

아래는 앱 `기기 추가` 화면에 있는 숙면매트 목록입니다. 표에 없는 모델이어도
Wi-Fi 로 앱에 등록돼 있으면 동작할 가능성이 높습니다 — 통합이 모델명을 보지 않고
**서버가 알려주는 제어 방식**을 따르기 때문입니다.

| 계열 | 모델 | 상태 |
| --- | --- | --- |
| **카본** (Wi-Fi) | EME500 · EME501 · EME520 · EME521 · EME550S · EME551D · EME650D · EME651P · EME652P | **EME-500 검증 완료.** 나머지는 될 것으로 봅니다 |
| **온수** (Wi-Fi) | EMW700 · EMW720 · EMW721 · EQM572 · EQM580 · EQM581 · EQM582 · EQM590 · EQM591 · EQM595 | 될 것으로 봅니다 (미검증) |
| **사계절** (Wi-Fi) | EMF440 · EMF450 · EMF500 · EMF501 · EMF510 · EMF520 · EMW750 · EMW751 · EMW753 | **난방만.** 냉방은 아래 참고 |
| **온수** (Bluetooth) | EQM530 · EQM550 · EQM551 · EQM552 · EQM553 · EQM555 · EQM560 · EQM561 · EQM562 · EQM565 · EQM570 · EQM571 · EQH20/40DN | **안 됩니다** |

**블루투스 모델이 안 되는 이유** — 폰과 직접 통신하고 클라우드를 거치지 않습니다.
HA 는 폰이 아니라서 붙을 방법이 없습니다. 앞으로도 지원 계획이 없습니다.

> `EQM551` 은 앱에서 Wi-Fi 목록과 Bluetooth 목록에 **둘 다** 있습니다. 같은 번호로
> 두 종류가 있는 것인지 확인하지 못했습니다. 이 모델을 쓰신다면 해보시고 알려주세요.

**「될 것으로 봅니다」의 뜻** — 통합은 모델별 표를 쓰지 않고 서버가 내려주는 값으로
동작합니다. 그래서 구조적으로는 다 됩니다. 다만 실기기로 확인한 것은 EME-500
싱글·더블 두 대뿐입니다. 안 되면 [제보](#제보하거나-문제를-알리실-때)해 주세요.

### 환기청정은 아직 미검증입니다

**규약은 앱에서 그대로 뽑았지만, 실기기로 한 번도 확인하지 않았습니다.**
집에 에어원이 없습니다.

- 동작하지 않을 수 있고, 값이 이상하게 보일 수 있습니다
- **구형은 안 됩니다.** 통신 방식이 아예 달라서(전원 값이 반대입니다) 통합이
  알아보고 건너뛰며 로그에 이유를 남깁니다
- 되든 안 되든 알려 주시면 고칩니다 — 아래 「제보하거나 문제를 알리실 때」

**모델 목록을 코드에 적어두지 않았습니다.** 신형이면 모델을 가리지 않고 잡습니다.
운전 모드도 서버가 그 기기의 지원 조합을 알려주므로 빠지는 것이 없습니다.

풍량이 「미풍·약풍·강풍」 대신 「터보·절전」만 보이는 기기가 있습니다.
전열교환기가 그렇습니다 — **잘못된 것이 아니라 그 기기에 풍량 단계가 없는 것**입니다.
앱에서도 같습니다.

### 사계절 매트의 냉방

사계절 매트는 펠티어 소자로 냉각합니다. 서버가 난방과 냉방에 **서로 다른 값 범위**를
내려주고, 계절 값 하나로 어느 쪽을 쓸지 정합니다.

난방은 그대로 쓰실 수 있습니다. **냉방으로 두시면 단계·온도 제어와 고온경고가
일시적으로 비활성**됩니다. 냉방 쪽 값 체계를 실기기로 확인하지 못했고, 난방 범위로
표시하면 잘못된 값을 보여주게 되기 때문입니다.

**사계절 매트를 쓰신다면 냉방으로 켜두신 상태에서 통계정보 파일을 받아
[제보](#제보하거나-문제를-알리실-때)해 주세요.** 필요한 값이 그 안에 다 들어 있습니다.
그게 모이면 냉방을 열겠습니다.

냉방으로 켜두셔야 하는 이유만 알아두시면 됩니다 — 난방 상태에서 받으면 냉방 관련
값이 비어 있어서 쓸모가 없습니다.

## 만들어지는 엔티티

매트 한 대당 이렇게 생깁니다. **기기에 없는 기능은 엔티티도 안 생깁니다** —
서버가 알려주는 기능 목록을 그대로 따릅니다.

| 엔티티 | 도메인 | 조건 |
| --- | --- | --- |
| 전원 | `switch` | `powerCtrl` 지원 시 |
| **난방 온도** | **`climate`** | **온도로 동작하는 매트** |
| **난방 단계** | **`select`** | **단계로 동작하는 매트** |
| 운전 상태 | `sensor` | 항상 |
| 오류 코드 | `sensor` | 항상 (기본 비활성) |
| 고온경고 | `binary_sensor` | 안전 기준값이 있을 때 |
| 오류 | `binary_sensor` | 항상 |

좌우 분리 모델은 온도·단계 엔티티가 **좌/우 두 개**씩 생깁니다.

환기청정은 이렇게 생깁니다.

| 엔티티 | 도메인 | 조건 |
| --- | --- | --- |
| 전원 | `switch` | 항상 |
| **운전 모드** | **`select`** | 서버가 고를 수 있는 모드를 알려줄 때 |
| **풍량** | **`select`** | 지금 모드에서 두 개 이상 고를 수 있을 때 |
| 목표 습도 | `number` | 제습·환기제습을 지원할 때 |
| 운전 상태 | `sensor` | 항상 |
| 필터 사용률 | `sensor` | 실외기가 알려주는 필터마다 하나 |
| 오류 코드 | `sensor` | 항상 (기본 비활성) |
| 오류 | `binary_sensor` | 항상 |

**모드 목록을 코드에 적어두지 않았습니다.** 서버가 그 기기가 지원하는 조합을
알려주므로 그것만 씁니다. 습도 범위도 서버가 준 값을 씁니다.

에어모니터를 쓰시면 **별도 기기**로 하나 더 생기고 공기질 센서가 거기 붙습니다.

| 엔티티 | 조건 |
| --- | --- |
| 미세먼지 · 초미세먼지 · 극초미세먼지 | 서버가 값을 주는 항목만 |
| 이산화탄소 · 온도 · 습도 | 〃 |
| 라돈 · 휘발성유기화합물 · 종합 공기질 | 〃 |

에어모니터가 없으면 공기질 센서가 본체 기기에 붙습니다.

### 온도 매트는 온도조절기, 단계 매트는 선택 목록

같은 숙면매트라도 기기에 따라 **온도(°C)** 로 동작하거나 **1~8단계**로 동작합니다.
서버가 어느 쪽인지 알려주므로 통합이 알아서 맞는 엔티티를 만듭니다.

| 기기가 쓰는 방식 | 만들어지는 엔티티 | 현재 온도 표시 |
| --- | --- | --- |
| 온도 (0.5도 단위) | `climate` — 서모스탯 카드 | 나옵니다 |
| 단계 (운전 대기 / 1~8단계) | `select` — 목록에서 고르기 | 없습니다 |

**단계 매트를 서모스탯이나 슬라이더로 만들지 않았습니다.**

서모스탯이 아닌 이유 — 서버가 단계 매트의 현재 온도를 아예 주지 않아 카드의 현재값
칸이 영구히 비고, 단계를 도(°)로 표시하면 "3단계"가 "3도"로 읽힙니다.

슬라이더가 아닌 이유 — 단계는 연속량이 아니라 9개의 이산 상태이고, 그중 `0` 은
숫자가 아니라 **운전 대기** 입니다. 좁은 카드에서 정확한 단계를 끌어 맞추기 어렵고,
슬라이더는 눈금에 이름을 붙일 수 없어 앱이 `운전 대기` 라 부르는 것을 `0 단계` 로
보여주게 됩니다.

목록에서 고르면 앱과 같은 말을 쓰고, 한 칸 빗나갈 일이 없습니다.
**한쪽만 운전 대기로 두는 것도 됩니다** — 반대쪽은 그대로 유지됩니다.

카본 매트는 단계, 온수 매트는 온도인 경우가 많지만 **모델명으로 단정할 수 없습니다.**
통합은 서버 값만 믿습니다.

## 언제 반영되나

**기기 조작이 즉시 반영됩니다.** 리모컨이나 본체로 바꿔도 바로 HA 에 나타납니다.
기기가 상태를 스스로 서버에 올리기 때문입니다 — 폴링이 아니라 실시간 수신입니다.

주기적 조회는 15분에 한 번뿐이고, 재접속 후 초기 동기화 용도입니다.

재시작 후에도 **1~2초 안에** 값이 채워집니다. 나비엔 서버는 저장된 상태를 조회하는
방법을 주지 않아서, 통합이 기기에 직접 "지금 상태를 알려달라" 고 물어봅니다.
그 왕복이 실측 1.4초였습니다.

**꺼져 있는 기기는 `사용할 수 없음` 으로 남습니다.** 응답할 수 없기 때문입니다.
전원을 켜면 채워집니다.

## 설치

**Home Assistant 2025.2 이상이 필요합니다.**

1. HACS → 사용자 지정 저장소에 이 저장소를 추가
2. `Navien Smart` 설치 후 Home Assistant 재시작
3. 설정 → 기기 및 서비스 → 통합 추가 → `Navien Smart`
4. 나비엔 스마트 앱 아이디와 비밀번호 입력

공간(home)이 여러 개면 어느 공간을 쓸지 고르는 화면이 나옵니다.

## 알아두실 것

### 나비엔 앱을 열면 HA 가 잠깐 밀려납니다

**나비엔은 한 계정에 세션을 하나만 허용합니다.** 나중에 로그인한 쪽이 앞의 세션을
끊습니다. 앱과 HA 가 같은 계정을 쓰면 서로 밀어냅니다.

실제로는 이렇게 됩니다.

- 앱을 열면 → HA 세션이 끊기고 **상태 갱신이 멈춥니다**
- HA 가 다음 조회 때 **자동으로 다시 로그인합니다** → 이번엔 앱이 로그아웃됩니다

**쓰는 데 큰 지장은 없습니다.** 통합이 알아서 복구하고, 매트 조작은 어느 쪽에서 하든
반영됩니다. 다만 앱을 보고 있는 동안 HA 화면이 멈춰 보일 수 있습니다.

### 그게 불편하면 가족 계정을 쓰세요

나비엔이 원래 제시하는 방법은 **가족 공유**입니다. 사람마다 계정을 따로 만들고
집주인이 초대해서 같은 공간을 씁니다. HA 를 가족 한 명처럼 넣으면 세션이 갈립니다.

1. 가족 구성원의 나비엔 계정을 준비합니다
2. 집주인 계정으로 **가족 초대**를 보내 같은 공간에 넣습니다
3. HA 에는 그 계정으로 로그인합니다

**다만 계정을 새로 만들려면 본인인증이 필요합니다.** 혼자 쓰시는 경우에는
추가 계정을 만들기 어렵습니다. 그럴 때는 위의 기본 방식으로 쓰시면 됩니다 —
그래서 이걸 필수가 아니라 선택으로 둡니다.

> 가족 계정으로 **제어까지** 되는지는 저희가 확인하지 못했습니다. 초대받은 계정의
> 권한이 조회로 제한될 가능성이 있습니다. 해보시고 알려주시면 이 문서를 고치겠습니다.

### 로컬(랜)로는 제어할 수 없습니다

찾아봤지만 **방법이 없습니다.** 매트가 Wi-Fi 기기라 기대할 만하지만, 순수하게
밖으로만 연결하는 클라이언트입니다.

- 매트의 **TCP 1~65535 전 범위에 열린 포트가 없습니다.** 핑만 응답합니다
- 앱에도 직결 코드가 없습니다. 프레임 프로토콜 상수가 남아 있으나 쓰이지 않고,
  UDP 코드는 환기청정 기기 등록 전용입니다
- 매트는 자기 전용 클라우드 엔드포인트로만 연결합니다. 앱조차 기기와 직접 통신하지
  않습니다

그래서 **인터넷이나 나비엔 서버가 끊기면 HA 에서도 제어할 수 없습니다.**

### 그 외

- 비밀번호를 5회 틀리면 나비엔이 비밀번호 재설정을 요구합니다.
  통합은 계정 상태를 바꾸지 않고 오류만 알립니다
- **고온경고는 경고일 뿐 제한이 아닙니다.** 앱과 같이 1~8단계 전부 설정할 수 있고,
  기준값을 넘으면 `binary_sensor` 가 켜집니다

## 다른 기기도 지원하려고 합니다

**환기청정 검증과 보일러 제보를 받고 있습니다.** 실기기 없이는 확인할 수 없어서,
쓰고 계신 분의 정보가 유일한 근거입니다.

| 대상 | 상황 |
| --- | --- |
| **환기청정 (에어원)** | 넣었습니다. **실기기 검증만 남았습니다** — 되는지 알려 주세요 |
| **보일러** | 상태 모델이 컨트롤러 종류별로 갈리고 각방 제어가 비트마스크로 인코딩되어 있어 오래 걸립니다. **자료는 모으지만 시점은 약속드리지 못합니다** |
| **사계절 냉방** | 난방은 이미 됩니다. 냉방 값 체계만 확인되면 열립니다 |
| 월패드 · 로비폰 · 상업용 | 서버 체계가 달라 범위가 아닙니다. 제보를 받지 않습니다 |

지원하지 않는 기기가 있으면 통합이 **로그에 이유를 남기고 통계정보 파일에 원본을
담아둡니다.** 아래 방법으로 그 파일만 보내주시면 됩니다.

## 제보하거나 문제를 알리실 때

**`통계정보 다운로드` 한 번이면 됩니다.** 무엇을 붙여야 하는지 고민하지 않으셔도 됩니다.

설정 → 기기 및 서비스 → **나비엔 스마트** → ⋮ → `통계정보 다운로드`

기기ID · IP · MAC · SSID · 아이디 · **별칭**이 전부 자동으로 가려집니다.
별칭에는 가족 이름이 들어가는 경우가 많아 함께 가립니다.

[이슈 남기기](https://github.com/ripe-avocado/navien_smart_ha/issues/new/choose) —
양식을 고르시면 필요한 항목을 안내해 드립니다.

| 양식 | 언제 |
| --- | --- |
| 환기청정 제보 | 에어원을 쓰고 계실 때 — 되든 안 되든 |
| 보일러 제보 | 보일러를 쓰고 계실 때 |
| 사계절 냉방 제보 | 사계절 매트를 냉방으로 쓰실 때 |
| 버그 신고 | 매트가 연동됐는데 동작이 이상할 때 |

## 개발자용 CLI

저장소의 `tools/navien_cli.py` 는 HA 없이 서버 응답을 직접 확인하는 도구입니다.
조회 전용이며 파이썬 표준 라이브러리만 씁니다.

```bash
python3 tools/navien_cli.py login
python3 tools/navien_cli.py devices          # 기기목록 + 기능 메타데이터
python3 tools/navien_cli.py watch            # 실시간 수신 (paho-mqtt 필요)
```

이슈에는 위 통계정보 파일을 붙이시면 되고, CLI 는 안 쓰셔도 됩니다.
